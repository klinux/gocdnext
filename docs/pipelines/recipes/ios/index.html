iOS (Xcode and Fastlane)

iOS compilation runs as a native script: job on an agent tagged macos. Xcode is not containerized, and gocdnext plugins remain Linux OCI images. This recipe uses Fastlane as the project-owned build interface: scan runs tests and gym archives the app into an .ipa plus dSYMs.

Complete the macOS agent and iOS toolchain/signing runbooks first. The full copyable project is in examples/ios-build/.

Section titled “Produce the signed archive”

The archive job runs only after the test stage succeeds. It declares exactly the signing secrets it needs and is restricted to push/manual on main:

The wrapper only owns secret materialization and cleanup. Its build operation is exactly:

The build lane creates a temporary keychain, runs read-only match, and calls gym. It then asserts that Fastlane returned both an IPA path and a dSYM zip; missing symbols fail the job rather than silently publishing an incomplete artifact set. An ensure block removes the keychain, while the wrapper removes the mode-0600 .p8 outside the workspace and provides a second keychain cleanup attempt on exit.

Caution

Do not add pull_request to the signed archive pipeline and do not expose its five secrets to PRs. Run PR tests in a separate, unsigned Simulator pipeline if contributors need feedback before merge.

Real-Mac acceptance

Section titled “Real-Mac acceptance”

Before calling the setup production-ready, run the example against the actual app and verify:

  1. routing selects the intended macos agent and xcodebuild -version matches DEVELOPER_DIR;
  2. scan executes the expected test plan and gocdnext ingests its JUnit file;
  3. match resolves the expected App Store profile without changing its repo;
  4. gym produces a signed .ipa and *.app.dSYM.zip, both downloadable from the run’s artifact list; and
  5. no signing value appears in live or persisted logs, and no temporary keychain remains after either a successful or deliberately failed archive.

The repository tests validate the YAML, Fastfile syntax, argv and cleanup contracts on Linux. They cannot substitute for this Xcode/Apple smoke.
